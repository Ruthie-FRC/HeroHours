SAFETY MECHANISMS:

Development → Production Protection:
  ✅ Test data command blocked when DEBUG=False
  ✅ Cannot accidentally use test data in production
  ✅ Multiple safety checks prevent mistakes

Production → Development Protection:
  ✅ Production data never mixed with test data
  ✅ Test users have specific ID range (1000-9999)
  ✅ Clear separation of concerns

═══════════════════════════════════════════════════════════════════════════════

QUICK DECISION:

  Are you working on the application locally?
  ├─ YES → Use DEVELOPMENT mode
  │        Set DEBUG=True, use setup_test_data
  │
  └─ NO → Use PRODUCTION mode
           Set DEBUG=False, import real users

═══════════════════════════════════════════════════════════════════════════════

SWITCHING MODES:

  Development → Production:
    1. Change DEBUG='False'
    2. Switch to PostgreSQL
    3. Add Redis URL
    4. Import real users (never use setup_test_data)

  Production → Development:
    1. Change DEBUG='True'
    2. Switch to SQLite (optional)
    3. Run setup_test_data --confirm
